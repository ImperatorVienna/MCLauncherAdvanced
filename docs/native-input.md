# 原生手柄接入

2026-10-13 已实现原生输入链路，独立于 Steam Input 和浏览器 Gamepad API。

## 逻辑分层

1. `launcher-platform/src/gamepad.rs`：gilrs 0.11.2 读取系统输入，后台单线程每 8ms 收集设备、轴和按键状态；保留事件快照，避免短按丢失。队列最多 256 帧，250ms 以前的输入不回放。窗口失焦、队列溢出或连接变化要求重新回到中立。
2. `src/input/nativeController.ts`：串行 IPC 轮询，每个设备独立适配器；一次只允许一台按住中的设备产生动作，松开后可接管。键鼠、失焦、输入法组合输入接管时清除旧状态。没有同时启用浏览器 Gamepad API。
3. `ControllerAdapter`：采用物理位置动作映射、0.25/0.18 死区滞回、350ms/100ms 方向与滚动重复。确认、返回、肩键和菜单只响应按下沿。方向十字键优先于摇杆；相反方向或确认/返回同时按下不产生这对动作。
4. `FocusManager`：唯一焦点路由，依次交给下拉菜单拦截、输入编辑会话、模态作用域及页面分区。设备层不维护 DOM 或页签状态。

## 位置映射

| 控件位置 | 动作 |
| --- | --- |
| 四面键下方（Xbox A / PS × / Nintendo B） | 确认 |
| 四面键右方（Xbox B / PS ○ / Nintendo A） | 返回 |
| 十字键 / 左摇杆 | 导航 |
| 左 / 右肩键 | 前 / 后页签 |
| 右摇杆上下 | 页面滚动 |
| Menu / Start | 菜单动作 |

提示绘制四面键位置，不依赖品牌字母。采用 gilrs 内置映射和系统设备输入，不读取 Steam 的环境映射，不针对每个硬件单独实现驱动。未建立自定义按键配置界面。

输入框：确认进入编辑，再确认或返回结束编辑，焦点留在字段；方向键可继续移动。实体键盘和输入法仍正常输入。仅启用且检测到 Steam 启动时请求 Steam 虚拟键盘。

## 验证边界

本机系统列出 DualSense Edge；脱离沙箱的 gilrs 只读枚举识别为 `PS5 Controller`，未把传感器、触摸板重复列为手柄。沙箱内枚举为空，因此沙箱中的零设备不能作为兼容性结论。

已自动验证动作映射、短按队列、断连/失焦/溢出重置、多设备互斥及现有分区导航、下拉、模态和输入编辑。不将自动化动作注入等同实际按键验证；有线/蓝牙按键方向、热插拔、Steam/gamescope、Windows/macOS 仍需实机测试。

库参考：https://docs.rs/gilrs/latest/gilrs/ 。Linux 构建依赖 pkg-config / libudev。

## 1.0.1 架构整理与验证

- 平台模块负责设备枚举、采样、轴方向规范化及有界队列；Tauri 的 `gamepad.rs` 只读取窗口焦点并转发 IPC。UI 提示、手柄示意图选择、焦点和导航仍在前端。
- Linux 使用 gilrs 的 Linux 后端；Windows 显式启用其 Windows Gaming Input（WGI）后端。复用 gilrs 已分离的系统实现，不复制两套采样业务流程。当前仅导出 Linux／Windows 手柄平台模块。
- 每次采样只枚举一次设备，同时生成设备清单和最终状态。IPC 取出事件队列不再复制事件帧；销毁采集服务时等待工作线程退出。
- 2026-10-19 Linux 主机只读枚举识别到 `PS5 Controller`。这只证明本机连接识别，不等同有线／蓝牙热插拔及实体按键的完整测试。
- Windows x86_64（MSVC）平台模块交叉编译检查通过；当前没有可用的 Windows 实机测试环境，不能据此声称已验证真实设备连接、热插拔或按键。
