# 原版与 Java 安装（Linux x86_64）

## 当前能力

版本配置页使用“正式版 / 快照版 / 预览版 → 大版本 → 具体版本”三级下拉，移除手填版本号。预览版包含预发布和候选发布版本；新版 26.x、旧版 1.21.x 按编号分组，无明确目标编号的历史周快照按年份分组，不猜测所属正式系列。默认配置名随版本选择更新；自定义名称不被覆盖。30 种图标使用本机官方 26.3 客户端材质，通过同一菜单选择；方块为贴图生成的 SVG 立体图，物品使用原始 PNG。来源和校验记录见 assets/installation-icons/sources.json。新建入口为“下载安装”，唯一提交按钮为“下载并安装”；一次创建配置、按填写名称创建版本目录并启动下载。以后编辑仅修改图标和 Java，使用“保存更改”。安装后名称及游戏版本固定，不通过编辑切换目录。仅安装，不包含认证或实际启动。

版本隔离采用常规目录结构：`<launcher>/.minecraft/versions/<版本目录名>/` 同时作为游戏工作目录和 gameDir，存档、模组、config、resourcepacks、shaderpacks、options.txt、日志等位于其中；版本 JSON/JAR 也在同一版本目录，公共 libraries、assets 留在 <launcher>/.minecraft 下。不增加 instances 层，不提供关闭隔离开关。一个新配置对应一个独立版本目录，目录名为玩家填写的配置名称。同一官方版本可以安装多份；名称与已有目录冲突（包括未登记的目录和大小写差异）时报“版本名冲突”，不覆盖或复用。后续导入必须保留 HMCL 等已有目录名，包括加载器后缀。Java 放在 `<launcher>/runtimes/java/`，多个配置共用。系统现有 Java 仅检测和使用，不移动、不修改，不设置系统 JAVA_HOME 或 PATH。

## Java 选择

启动时扫描系统及托管 Java，规范化去重最多 128 个候选；支持手动刷新。运行候选 Java 的 `-XshowSettings:properties -version`，确认版本与本机构建架构；每次检测最多 5 秒，不执行 shell。扫描 JAVA_HOME、PATH、/usr/lib/jvm、/usr/lib64/jvm、/usr/java、/opt/java、/opt/jdk 与托管目录。

每个配置保存可选的 `javaPath`；暂未选择 Java 时不保存此字段。玩家可选任意已检测运行时或暂不选择，推荐主版本不会过滤可选项或覆盖现有选择。游戏文件安装独立于 Java：没有 Java 也可以安装；已安装状态只检查游戏文件，不因 Java 缺失而变成未安装。

仅点击“下载 Java”才执行独立任务，复用底部进度、取消与文件任务互斥。常用下载项为 8/11/16/17/21/25，游戏声明其他主版本时也加入下载菜单。下载校验 SHA-256、临时解压并实际运行验证后保存；不会修改系统环境，不会自动切换配置选择。下载完成重新检测，玩家自行选用。尚未支持任意自定义 Java 可执行文件的文件选择器。

推荐优先读取官方 JSON 的 `javaVersion.majorVersion`。缺少声明时，已确认的旧正式版回退表为：1.0–1.16.x → 8；1.17.x → 16；1.18.x、1.19.x、1.20–1.20.4 → 17；1.20.5+（1.20 系列）和 1.21.x → 21。未知系列和无声明的历史快照只显示无法获取推荐，不阻止安装。推荐网络请求失败也不影响手动选择。

## 下载与提交

- HTTPS 官方清单 → 校验版本 JSON SHA-1 → 校验资源索引 → 生成安装计划。
- 计划包含 client JAR、符合 Linux 规则的库、旧版原生库分类包、资源对象和日志配置；按路径去重，冲突报错。
- 4 个下载工作线程；现有文件先检查长度与完整哈希，正确文件复用；每个失败文件最多尝试 3 次。单文件未完成的临时文件不作为有效缓存，暂不提供 HTTP Range 断点续传。
- 文件写临时路径、大小/哈希验证与同步后原子替换。只允许官方元数据、资源、库、Adoptium 与其 GitHub 发布下载主机；重定向同样校验。
- 准备旧版 natives、virtual assets / resources 映射。路径不得越界，拒绝游戏路径内部的符号链接；JDK 解压限制总量、文件数和链接目标，原生 ZIP 不接受越界路径或符号链接。
- 版本 JSON 的本地 id 和 JAR 文件名与配置目录名一致（官方 JSON 先校验再适配，安装记录保存适配后哈希）。全部步骤成功才写 `versions/<配置名>/launcher-install.json`，记录可选 Java 检测结果与文件清单（配置自身的 javaPath 才是后续选择来源）。列表的安装状态是轻量存在性/大小检查；完整哈希验证由“校验 / 修复”执行，不把列表状态当作持续完整性监测。

## 任务与界面

新建命令接受配置和修订号，由后端检查名称与目录冲突、创建目录、保存记录并启动下载；继续安装/修复只接受已有配置 ID，不接受前端任意下载 URL 或路径。后台同时只允许一个文件任务，安装时禁止修改配置和退出进程，仍可浏览页面；取消会在当前文件块或网络等待结束后生效。使用同步客户端超时：连接及每次阻塞读取最多 15 秒，文件传输每轮读取检查 300 秒预算（进行中的读取最多再等待 15 秒），元数据请求配置 30 秒超时。不在普通下载线程上配置异步 read_timeout。

进度为分阶段字节进度，Java、游戏、解压阶段有各自标签。底部进度区域参与 flex 布局，压缩页面和滚动条，不覆盖内容；无进行中任务时隐藏。取消/失败可重试复用通过校验的文件。安装按钮失去可用状态时焦点移至取消任务；任务结束后回到可用控件。

## 架构与测试入口

`launcher-install`：download（网络/校验/并发）、java（探测/托管安装）、minecraft（官方元数据/计划/提交）。无 Tauri 或 DOM 依赖。桌面 `install_commands` 提供互斥任务、进度轮询和取消；前端 `useInstaller` 将任务接入现有组件。构建目标仅启用 Linux x86_64 glibc 安装策略，其他平台返回明确不支持，不伪装 Linux 包可用。

独立网络验证例程：`cargo run --manifest-path crates/launcher-install/Cargo.toml --example install_smoke -- /tmp/<test-directory> <version>`。仅允许临时目录，不默认触碰真实游戏目录。`java_smoke` 单独验证托管 JDK 分支。

## 强制隔离与已有版本目录

后端 instance_directory 统一解析 versions/<版本目录名>，拒绝越界与目录符号链接。安装文件根目录仍是 .minecraft，版本 JSON/JAR 与原生库放在 versions/<版本名>，资源与依赖共享。历史版本 map_to_resources 映射也位于版本目录内部。安装状态继续读取原来的版本安装记录；无需将现有原版迁移或重新完整下载。

不搬动或删除其他启动器的存档、模组与设置。目录布局兼容不等于已实现任意第三方版本导入：当前还未接入自动扫描/导入 HMCL 配置、Forge/NeoForge 继承解析和游戏启动，不能把这些目录当作已完成安装的原版直接覆盖修复。后续启动必须以该版本目录设置工作目录和 --gameDir（或历史参数），公共 assets/libraries 用绝对路径指向 .minecraft 下对应位置。

全局启动器配置文件仍为 <launcher>/launcher-library.json；托管 Java 共用安装目录，Java 选择按配置保存。此前 instances 方案从未打包发布，本次只改源码，不操作用户数据目录。

## 配置与目录生命周期

新建使用 `create_instance`，修复使用 `start_installation`，删除使用 `delete_instance`；普通 `save_library` 只允许原有记录的图标、Java、选择状态修改，不能绕过生命周期新增/移除配置或变更目录。配置使用必填 `directoryName` 字段，库使用 schemaVersion 2 和 `instances`。现有数据已直接备份改写，不保留旧字段兼容分支。新配置拒绝目录别名；删除仍检查目录是否被其他配置引用，避免损坏数据时误删。

删除弹窗展示目录和永久删除提示，删除范围包含整个版本目录（存档、模组、资源包、光影、设置及安装文件）；不删除公共 libraries/assets 和 Java。后端在阻塞工作线程中持有存储锁，和安装/配置保存互斥；检查修订号和路径、拒绝目录根符号链接。嵌套符号链接只删除链接本身。目录清理失败保留记录以便重试；目录已删除但记录保存失败时明确报错并可重试删除。取消或失败的安装保留配置与下载文件，通过“继续安装”复用已校验文件。
